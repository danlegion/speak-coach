# Speak Coach App — Thin Client + Mailbox (M1)

Implements the design in `../references/station-app-design.md`: the client
(phone Pocket mode, Portal Station mode) only captures and displays; all
transcription, measurement, and coaching judgment happen on Felix's side in
one pass.

## Pieces

- `server.py` — stdlib-only mailbox server.
  - `GET /` app page, `GET /api/plan` today's plan, `POST /api/upload`
    (raw recording body; `drill` + `mode` query params; Predict taps in
    `X-Predict-Pace` / `X-Predict-Fillers` headers), `GET /api/status`.
  - Uploads land in `../recordings/<yyyy-mm-dd>-<drill>-<hhmmss>/` with
    `meta.json`. Optional `SPEAK_COACH_TOKEN` shared secret (header
    `X-App-Token`). Port from `PORT` env (default 8765).
- `static/` — the client: one page, brief → record (MediaRecorder, 3-2-1
  countdown, timer) → predict → upload → poll → scorecard. Wide landscape
  screens label themselves Station mode; everything else Pocket mode.
- `plan.json` — today's session plan, generated by Felix from
  `training_state.md` + the drill library.
- `process_session.py` — Felix's processing pass for one session dir:
  ffmpeg-decodes to PCM, transcribes locally with faster-whisper (the
  ndarray input path; the PyAV decode path is version-fragile), runs
  `../tools/analyze-audio.py` (or `analyze-video.py`), runs
  `../tools/repetition.py`, merges `metrics.json`. It never writes
  `scorecard.json` — judgment is the coach's step.
- `../tools/repetition.py` — phrase-repetition counter (Daniel's filler
  pattern): repeated n-grams (2–6 words), maximal phrases, events/min.

## Run locally

```sh
cd app && PORT=8765 python3 server.py
# process an uploaded session:
python3 app/process_session.py recordings/<session-dir>
```

## Hosting (decided 2026-10-26: Render)

Felix's VM cannot host this for the phone: the Muse Tailscale client is
outbound-only (accepts no connections, hosts nothing). Daniel chose Render
— his existing pattern (MiFicha). Live service: `speak-coach` →
https://speak-coach-1hag.onrender.com (free plan, Oregon, auto-deploys from
`main`). HTTPS out of the box, which `getUserMedia` requires outside
localhost; reachable from the phone anywhere and from the Portal browser
later. The access token (`SPEAK_COACH_TOKEN`) is set in the service env and
kept locally in `app/.token` (gitignored); the client asks for it once per
device and stores it in localStorage.

Operational notes:
- Free tier sleeps when idle: the first hit after a quiet spell can take
  ~30–60 s to wake. Warm requests answer in about a second.
- Session ids are dated in the server's clock (UTC on Render) — a Monday
  evening PT recording may carry Tuesday's date. Harmless; noted so nobody
  "fixes" it later.
- Recordings sit on the service's disk only until Felix's sync pulls them
  into the VM's `recordings/` (the durable store).
